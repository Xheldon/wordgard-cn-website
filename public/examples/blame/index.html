示例：原产地追踪

在本示例中，我们将构建一个功能，用于追踪添加到编辑器中的所有内容的来源。为简化起见，我们的来源将仅为三种颜色之一（我们将其作为内容的背景色显示），但它也可以是用户引用之类的信息。

责任归属图

我们将定义一种数据结构，用于记录文档中每个部分是由谁（即哪种颜色）插入的。该结构由两个数组表示：一个数字数组，指示每个部分的结束位置；一个字符串数组，存储对应的颜色。由于这些部分覆盖了整个文档，因此无需存储它们的起始位置。第一个部分从 0 开始，其余部分则从前一部分的结束位置开始。

import {ChangeSet} from "wordgard/doc"

class BlameMap {
  end: readonly number[]
  color: readonly string[]

  constructor(end: readonly number[], color: readonly string[]) {
    this.end = end
    this.color = color
  }

  update(changes: ChangeSet, blame: string) {
    let end: number[] = [], color: string[] = []
    function add(to: number, col: string) {
      // 合并颜色相同的相邻部分
      if (color.length && color[color.length - 1] == col) {
        end[end.length - 1] = to
      } else {
        end.push(to)
        color.push(col)
      }
    }
    let i = 0
    changes.iterGaps((fromA, toA, fromB, toB) => {
      // 未更改范围：复制部分
      let off = fromB - fromA, pos = fromB
      for (; i < this.end.length; i++) {
        let next = this.end[i] + off, end = Math.min(toB, next)
        if (end > pos) {
          add(end, this.color[i])
          pos = end
        }
        if (next >= toB) break
      }
    }, (fromA, toA, fromB, toB) => {
      // 替换范围：分配当前颜色
      if (toB > fromB) add(toB, blame)
    })
    return new BlameMap(end, color)
  }
}

变更集的 iterGaps 方法 会精确告知您文档的哪些部分在变更后保持不变（传递给第一个回调），哪些部分被替换（传递给第二个回调）。责任图的 update 方法利用这一信息，将与未变更范围重叠的片段复制到新集合中，并用当前激活的颜色填充任何插入的内容。

州字段

这为我们提供了一种在文档变更中追踪责任信息的方法。为了在编辑器中保留此类信息，我们需要将其存储在一个状态字段中。BlameState 类就是我们将存储在该状态中的对象。它包含当前激活的颜色、责任映射以及一组用于显示该责任映射的装饰。

import {GardState, Transaction} from "wordgard/state"

const setColor = Transaction.Effect.define<string>()

class BlameState {
  blame: BlameMap
  deco: RangeSet<Decoration.Range>
  activeColor: string

  constructor(blame: BlameMap, active: string) {
    this.blame = blame
    this.activeColor = active
    this.deco = blameDeco(blame)
  }

  update(tr: Transaction) {
    let active = this.activeColor
    for (let e of tr.effects)
      if (e.is(setColor)) active = e.value
    if (!tr.docChanged && active == this.activeColor) return this
    let blame = this.blame.update(tr.changes, active)
    return new BlameState(blame, active)
  }
}

const blameField = GardState.Field.define<BlameState>({
  create(state) {
    throw new Error("Field should always get an init value")
  },
  update(value, tr) {
    return value.update(tr)
  },
  toJSON(value) {
    return {
      end: value.blame.end,
      color: value.blame.color,
      active: value.activeColor
    }
  },
  fromJSON(json) {
    let blame = new BlameMap(json.end, json.color)
    return new BlameState(blame, json.active)
  },
  provide: f => Decoration.Range.source.of(s => s.field(f).deco)
})

为了能够更改活动颜色，我们定义了一个 setColor 效果，并使状态更新逻辑检查该效果是否存在。

状态字段的 create 方法仅会抛出错误。由于我们需要初始化活动颜色，我们将使用其 init 方法 来用自定义初始化器覆盖此行为。

state 字段定义了 toJSON 和 fromJSON 函数，以便它可以通过 toJSON 作为 state 的一部分进行序列化。此演示实际上并未使用该功能，但能够跨会话保留归责信息听起来很有用。

blameDeco 函数将 blame 映射转换为一组属性装饰。由于对于给定颜色，范围装饰对象将被频繁使用，我们确保每种颜色仅创建一次这些对象。

import {RangeSet, Decoration} from "wordgard/editor"

function blameDeco(map: BlameMap) {
  return RangeSet.create<Decoration.Range>(add => {
    for (let pos = 0, i = 0; i < map.end.length; i++) {
      let end = map.end[i], col = map.color[i]
      if (col) add(pos, end, colorDeco(col))
      pos = end
    }
  })
}

const decoCache = new Map<string, Decoration.Range>()

function colorDeco(color: string) {
  let found = decoCache.get(color)
  if (!found) {
    found = Decoration.Range.attribute(
      "style", `background-color: ${color}`)
    decoCache.set(color, found)
  }
  return found
}

结果

最后，blameTracking 函数返回启用此功能的扩展。它将应开始的激活颜色作为选项传入，并相应地初始化状态字段。

function blameTracking(
  config: {startColor: string}
): GardState.Extension {
  return blameField.init(state => new BlameState(
    new BlameMap([state.doc.length], [""]),
    config.startColor))
}
