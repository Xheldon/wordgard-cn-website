示例：配置

本示例讨论 Wordgard 编辑器的配置方式，并展示一些常见的使用模式。

配置的作用

几乎所有配置都是可选的。编辑器在没有模式的情况下将拒绝初始化，但如果您在 doc 字段 中传入一个文档节点，则可以完全省略 config 字段。

但是，这样的编辑器将没有菜单、撤销历史记录，也不包含模式元素扩展中的任何扩展，例如输入规则或特定于元素的键盘绑定。

该库的一项设计原则是，核心仅提供编辑平台，而大部分实际的编辑行为由扩展实现。特定的配置可以决定哪些部分使用库提供的功能，哪些部分使用其自定义实现或第三方包。

配置存储在编辑器状态中。影响 UI 组件的部分通过状态实现——每当状态更新时，编辑器都会自动同步配置的变化。

方面

大多数扩展通过facets直接或间接地工作。其中许多是在核心库中定义的，但您也可以定义自己的扩展。

const saveCheck = GardState.Facet.define<
  (wg: Wordgard) => string | null
>()

function save(wg: Wordgard) {
  let problems = wg.state.facet(saveCheck)
    .map(ch => ch(wg)).filter(x => x != null)
  if (problems.length) {
    Dialog.show(wg, {
      label: "Cannot save: " + problems,
      submitLabel: "Too bad"
    })
  } else {
    makeSaveRequest(wg.state.doc)
  }
}

该代码定义了一个包含函数的 facet，这些函数用于检查编辑器内容是否处于可保存状态。save 函数会调用这些函数。如果其中任何一个函数返回字符串，则报告无法保存；否则，将保存文档。

要注册保存检查，您需要在配置中添加一个扩展，例如 saveCheck.of(wg => { ... })。

Facet 源可以是动态的，即从状态的其他方面计算得出。这使得它们也能用于控制那些在编辑器生命周期中不会保持不变的内容，例如打开的面板。

配置结构

config 字段 接受一个 GardState.Extension 值。这是一种递归类型，它要么是一个包含 extension 属性的对象，要么是一个扩展数组。通常您无需关心具体处理的是哪一种。返回扩展的函数的值可以包含在您的扩展中，并且能够直接正常工作。

一种典型模式是，对于某个特定功能（例如 撤销历史），将其导出为一个函数，该函数组合了实现该功能所需的所有较小扩展。

因此，像这样的配置……

config: [history(), basicSchema()]

...实际上会扩展成一棵大树，可能看起来像这样：

config: [
  [                                  // 历史记录()
    historyStateField,
    historyConfig.of(config),
    Command.handler(undoCmd, undo),
    Command.handler(redoCmd, redo),
    undoButton,
    redoButton
  ],
  [                                  // 基础模式
    GardState.schemaElement.of(Doc),
    [                                // 基本标记()
      [                              // 加粗()
        GardState.schemaElement.of(Strong),
        strong.button,
        strong.keyBinding,
      ],
      [                              // 强调()
        GardState.schemaElement.of(Emphasis),
        emphasis.button,
        emphasis.keyBinding
      ],
      [                              // link()
        GardState.schemaElement.of(Link),
        link.button,
        link.keyBinding,
        link.tooltip,
        link.pasteOver
      ]
    ],
    [                                // 段落()
      GardState.schemaElement.of(Paragraph),
      paragraph.button,
      paragraph.keyBinding
    ],
    [                                // heading()
      GardState.schemaElement.of(Heading),
      heading.button1, heading.button2, heading.button3,
      heading.keyBindings,
      heading.createOnHash
    ],
    GardState.schemaElement.of(LineBreak)
  ]
]

通常，您无需了解所有这些内部扩展，除非您希望微调配置以省略或替换其中某些扩展。在这种情况下，您不会使用 bundle 函数，而是逐个包含您需要的部分。正是为了实现这一点，许多此类内部扩展（至少那些可以独立有意义使用的扩展）也被导出。

当某个扩展在配置树中出现多次时，仅使用优先级最高的那次出现。因此，只要扩展将其内部元素定义为常量，如果您使用了两个都包含相同子扩展的扩展，您的配置在解析过程中将对其进行去重。

优先级

对于许多类型的扩展，如果它们在配置中多次出现，其相对优先级将决定它们的行为。例如，键盘绑定或事件处理器会按照优先级顺序获得处理按键的机会；包装装饰会包裹其目标，使得优先级较低的装饰包裹优先级较高的装饰。

您可以通过更改扩展树中扩展的顺序，或为扩展分配显式的 优先级 来控制相对优先级。例如，在此配置中，记录 A 的按键绑定将首先处理 Ctrl-Space（如果其处理程序返回 false，则记录 B 的处理程序将有机会处理该按键）。

[
  KeyBinding.define({
    key: "Ctrl-Space",
    run() { console.log("A"); return true }
  }),
  KeyBinding.define({
    key: "Ctrl-Space",
    run() { console.log("B"); return true }
  })
]

然而，如果您将第二个绑定包装在 GardState.prec.high（或将第一个包装在 GardState.prec.low）中，顺序将会反转。

重构

当编辑器的配置在其生命周期内可能发生变化时，一种直接的模式是创建一个根据某些参数生成配置的函数，并在需要更改配置时，使用该函数配合 GardState.reconfigure 来更新您的配置。

import {Wordgard, menuBar} from "wordgard/editor"
import {basicSchema} from "wordgard/schema"
import {GardState} from "wordgard/state"

function config(withMenu) {
  return [basicSchema(), withMenu ? menuBar() : []]
}

const wg = Wordgard.create({
  config: config(true)
})

// 当我们不再需要菜单时
wg.dispatch({
  effects: GardState.reconfigure.of(config(false))
})

重新配置状态不会重置任何不需要重置的内容。在旧配置和新配置中都存在的任何状态字段将保持不变，不受更改影响的方面输出值也保持不变。

在需要更改配置控制的代码仅涉及配置的一部分，且不应重新配置整个编辑器（因为它只是一个编辑器扩展，而非编辑器的所有者）的情况下，您有两个选择。

如果您仅需注入某些扩展（例如，在实现一个命令时，该命令生效后需要某些支持扩展处于激活状态），您可以在分派的交易中将 GardState.appendConfig 用作效果。您应首先检查您的扩展是否已激活，以避免重复追加。

更细粒度的机制是使用扩展区室。区室封装了初始配置的一部分，在必要时，该部分可以被替换为一组不同的扩展。

此代码定义了一个扩展，当您按下 Ctrl-Space 时，会将编辑器背景切换为粉红色，再次按下时则恢复为默认背景。

import {KeyBinding, Wordgard} from "wordgard/editor"
import {GardState} from "wordgard/state"

const theme = Wordgard.theme({
  "&": {backgroundColor: "pink"}
})

const pinkCompartment = GardState.Compartment.define()

function toggle(wg: Wordgard) {
  let current = pinkCompartment.get(wg.state)
  let empty = Array.isArray(current) && !current.length
  return {
    effects: pinkCompartment.reconfigure(empty ? theme : [])
  }
}

export function togglePink() {
  return [
    pinkCompartment.of([]),
    KeyBinding.of({key: "Ctrl-Space", run: toggle})
  ]
}

它使用 Compartment.get 来判断主题是否处于活动状态，并使用 reconfigure 来分发一个更新编辑器配置的效果。
