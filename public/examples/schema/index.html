示例：架构

每个 Wordgard 编辑器都有一个 模式，它定义了文档中可能出现的元素集合（节点和标记类型）以及它们之间的关系。

配置您的架构

声明编辑器模式最简单的方法是在配置中包含一个基本模式包（basicSchema、fullSchema或inlineSchema），然后根据需要添加其他元素。

import {basicSchema, orderedList, bulletList} from "wordgard/schema"
import {Wordgard} from "wordgard/editor"

const wg = Wordgard.create({
  doc: "<ul><li>Item A</li><li>Item B</li></ul>",
  config: [
    basicSchema(),
    orderedList({blockItems: false}),
    bulletList({blockItems: false})
  ]
})

其中一些支持额外的配置，但只有在直接添加它们时才能提供。在这种情况下，我们将列表类型设置为使用包含内联内容的项，而这些列表类型通常支持在其项中包含块级内容。

如果您需要在配置中包含原始节点或标记类型，则必须将其包裹在 GardState.schemaElement 中。

在需要于创建编辑器状态之前访问模式的情况下，您可以先解析一个配置，使用该配置定义的模式，然后基于此创建状态。

import {GardState} from "wordgard/state"
import {basicSchema, alignment} from "wordgard/schema"
import {Paragraph} from "wordgard/types"
import {Leaf} from "wordgard/doc"
import {Wordgard} from "wordgard/editor"

const config = GardState.Configuration.create([
  basicSchema(),
  alignment()
])

const schema = config.schema!

// 对模式执行操作
const doc = schema.doc([
  Paragraph.create([Leaf.text("hi")])
])

const wg = Wordgard.create({doc, config})

也可以在不使用配置的情况下创建模式，方法是直接调用 Schema.define。在此处，您无法提供编辑器扩展，而必须传入实际的模式元素（来自 "wordgard/types" 或自定义定义）。

import {Schema} from "wordgard/doc"
import {Doc, Paragraph, Strong} from "wordgard/types"

const schema = Schema.define([
  Doc,
  Paragraph,
  Strong
])

这主要适用于那些实际上并未创建编辑器的脚本，例如处理 Wordgard 文档的节点脚本。

自定义元素

在富文本文档中包含恐龙往往非常重要。因此，在本示例中，我们将为它们创建一个自定义叶子类型。

import {Leaf, ValidationError, parse} from "wordgard/doc"
import {Wordgard} from "wordgard/editor"

const dinoNames = ["Brontosaurus", "Pterodactyl", "Stegosaurus",
                   "Triceratops", "Tyrannosaurus"]

export const Dino = Leaf.Type.define<string>("Dino", {
  inline: true,
  validate: type => {
    if (!dinoNames.includes(type))
      throw new ValidationError(`Unknown dinosaur type: ${type}`)
  },
  shape: {
    element: "document-dino",
    attributes: type => ({"data-name": type}),
    readElement: elt =>
      elt.getAttribute("data-name") ?? parse.Reject
  },
  selectable: true,
})

这是一个简单的内联叶子定义，它接受一组恐龙名称中的一个作为参数，并将自身渲染为 <document-dino data-name="Triceratops"> 元素。

我们将定义一组样式，使该元素真正看起来像恐龙。

export const dinoStyles = Wordgard.styles({
  "document-dino": {
    display: "inline-block",
    height: "40px",
    width: "40px",
    border: "1px solid #0ae",
    borderRadius: "4px",
    backgroundColor: "#ddf6ff",
    verticalAlign: "bottom",
    backgroundSize: "contain",
    ...dinoNames.reduce<any>((s, name) => {
      s[`&[data-name=${name}]`] = {
        backgroundImage: `url(dino/${name}.png)`
      }
      return s
    }, {})
  }
})

用户需要插入恐龙，因此让我们添加一个简单的插入命令。

import {GardSelection} from "wordgard/state"
import {Command} from "wordgard/command"

export const insertDino: Command<string> = (
  wg: Wordgard,
  name: string
) => {
  let {from, to} = wg.state.selection.replacementRange
  return {
    changes: {from, to, insert: [Dino.of(name)], fit: true},
    scrollIntoView: true,
    userEvent: "insert.dino",
    selection: (cx, changes) => {
      let found = changes.findInserted(tag => tag.type == Dino)
      return found == null ? null : GardSelection.cursor(found + 1)
    }
  }
}

我们将通过菜单使该命令可访问。对于像这样的子菜单，如果我们预先知道它应包含的内容，通常直接在定义中提供内容更为实用。

import {Menu} from "wordgard/command"

export const dinoMenu = Menu.Submenu.define({
  label: dinoIcon,
  description: "Insert Dino",
  parent: Menu.Group.insert,
  rank: 90,
  content: dinoNames.map(name => Menu.Button.define({
    label: name,
    run: Command.bind(insertDino, name),
  }))
})

这为我们提供了所需的功能。为了方便起见，我们将它们封装在一个函数中。

import {GardState} from "wordgard/state"

export function dino(): GardState.Extension {
  return [
    GardState.schemaElement.of(Dino),
    dinoMenu,
    dinoStyles
  ]
}

仅列表模式

让我们通过一个更改架构结构的示例来说明。对于大纲式编辑器，我们希望确保文档的顶层始终是一个列表。

我们可以使用现有的列表图定义，但必须更改它们的关系。默认的 Doc 图允许类型为 Node.Group.Content 的内容，这是一个用于通用块级内容的组。在我们的编辑器中，我们希望将其缩小为仅 BulletList。

config: [
  basicSchema(),
  bulletList(),
  GardState.schemaElement.of(
    Schema.Override.plotContent(Doc, BulletList)),
  /* ... */
]

这已经相当有效了。不过，一旦你使用退格键合并两个列表项，就很难开始新项，因为默认的 enter 命令不知道在这种架构下该如何表现。

让我们添加一个处理程序，使其在用于顶级列表项中的空文本块（但不是该列表项的第一个块）时，能够拆分列表项。

import {Plot} from "wordgard/doc"
import {ListItem} from "wordgard/types"
import {Command, enter} from "wordgard/command"

export const splitOnEnter = Command.handler(enter, wg => {
  let {sel} = wg.state
  if (!sel.selection.isCursor || sel.head.depth > 3)
    return false
  let block = sel.head.textblockParent
  if (!block || block.node.contentLength || block.index == 0)
    return false

  return {
    changes: {from: block.before, insert: [Plot.End, ListItem]}
  }
})

经过这一调整，我们便获得了一个尚可用的仅列表编辑器。

内联模式

可以设置一个 Wordgard 模式，其中文档为单个文本块，使用 inlineSchema 或 InlineDoc（或定义您自己的文档类型）。

只需稍加样式，您就可以让此类编辑器看起来像一个支持富文本的输入框。

import {Wordgard} from "wordgard/editor"

const inlineEditor = Wordgard.theme({
  "&": {
    display: "inline-flex",
    borderRadius: "4px",
    width: "10em"
  },
  "wg-scroller": {
    overflowX: "auto"
  },
  "wg-content": {
    whiteSpace: "pre",
    padding: "4px 6px"
  }
})

好了，这就是内联富文本字段。
