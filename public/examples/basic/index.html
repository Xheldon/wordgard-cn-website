示例：基础编辑器

本示例介绍了库接口最基本的部分，即用于从预定义的配置元素创建编辑器、将其添加到网页以及读取更改后的文档的功能。

创建编辑器

要获得一个可用的编辑器，您至少需要一个文档模式，并且通常还需要包含撤销历史记录以及一个用于显示菜单的扩展。

basicSchema 扩展（段落、标题、强调、链接）提供了一组良好的基础模式元素，允许您通过逐步在配置中包含它们来添加额外元素（例如 列表）。如果您希望一次性获取 "wordgard/schema" 模块提供的所有内容，您可以包含 fullSchema。

此代码设置了一个简单的编辑器，并将其添加到 ID 为 editor-parent 的元素中。

import {Wordgard, menuBar} from "wordgard/editor"
import {basicSchema, orderedList} from "wordgard/schema"
import {history} from "wordgard/history"

const wg = Wordgard.create({
  parent: document.querySelector("#editor-parent"),
  doc: `<p>A starting document.</p>`,
  config: [
    Wordgard.label("Demo editor"),
    basicSchema(),
    orderedList(),
    history(),
    menuBar()
  ]
})

doc 选项也可以是一个包含文档结构的 DOM 元素、JSON 格式的文档，或现有的 Wordgard 文档。

编辑器配置源自您提供的扩展树（其中可能包含更多嵌套数组的数组）。诸如 basicSchema 和 history 之类的函数会返回实现其所提供功能的扩展集合。在初始化时，编辑器会根据这些扩展创建一个完整的 配置，并将其存储在编辑器状态中。

Wordgard.label 会为可编辑元素添加 aria-label 属性，以便屏幕阅读器能够对其进行描述。通常建议在配置中包含此项。

编辑器关联有两个重要的 DOM 元素。外部包装元素可通过 dom 属性访问。如果您未传递 parent 选项，则可以通过将该元素放置在页面的任意位置来手动定位编辑器。支持移动编辑器，甚至将其移动到另一个框架中。

编辑器中包含文档本身的可编辑元素通过 contentDOM 属性暴露。您通常不需要与此元素交互（直接修改其内容无效），但当用户聚焦编辑器时，该元素将获得焦点。

编辑器状态

编辑器的状态可通过编辑器对象的 state 属性访问。它包含了编辑器中正在发生的大多数信息。从中可以获取的主要信息是文档的当前结构，位于其 doc 属性下。

要获取当前内容的 HTML 格式，您可以这样做：

import {serialize} from "wordgard/doc"
console.log(serialize(wg.state.doc).toHTML())

如果您希望将文档存储为 JSON 结构，请使用 wg.state.doc.toJSON()。您可以将生成的值传递给 Wordgard.create 的 doc 字段，以使用该文档创建一个新的编辑器。

当用户编辑文档或发生其他状态变更时，编辑器会创建新的 状态 对象来表示新情况。现有对象不会被修改，因此保留旧对象并期望其与编辑器保持同步是行不通的。

加载新文档

如果您想向用户显示另一个文档，请勿通过替换现有编辑器中的文档内容来更新该编辑器。这样做会保留来自现有编辑状态的辅助状态，例如撤销历史记录。

相反，请创建一个具有全新状态的新编辑器。由于文档无论如何都需要重绘，尝试保留旧编辑器并不会节省太多额外开销。请从页面中移除其外部 DOM 元素，并在其位置放置一个新编辑器。
